## 🎯 测试目标

验证本地图片导入链路在桌面端和 Web 环境下都能稳定识别图片，并且在 `File.type` 为空时仍能根据扩展名正确兜底。

本测试不覆盖安装包构建、安装、更新流程，只覆盖功能代码行为。

## 🔍 功能点分解

### 1️⃣ 桌面端工具栏添加图片

| 测试点 | 优先级 | 输入 | 预期结果 |
|--------|--------|------|----------|
| 添加 PNG 图片 | P0 | `.png` | 图片插入当前画布 |
| 添加 JPG 图片 | P0 | `.jpg` / `.jpeg` | 图片插入当前画布 |
| 添加 WebP 图片 | P0 | `.webp` | 图片插入当前画布 |
| 添加空 MIME 图片 | P0 | 扩展名有效、MIME 为空 | 图片插入当前画布 |
| 取消选择文件 | P1 | 关闭文件选择器 | 不报错、不插入元素 |
| 选择非图片文件 | P1 | `.txt` / `.pdf` | 不作为图片插入 |

### 2️⃣ 画布拖拽与粘贴

| 测试点 | 优先级 | 输入 | 预期结果 |
|--------|--------|------|----------|
| 拖拽 PNG 到画布 | P0 | `.png` | 图片出现在拖拽位置附近 |
| 拖拽空 MIME JPG 到画布 | P0 | `.jpg` 且 MIME 为空 | 图片正常插入 |
| 粘贴图片文件 | P0 | 剪贴板图片文件 | 图片插入画布 |
| 拖拽多文件混合 | P1 | 图片 + 非图片 | 图片插入，非图片不按图片处理 |

### 3️⃣ 素材库上传

| 测试点 | 优先级 | 输入 | 预期结果 |
|--------|--------|------|----------|
| 上传 AVIF | P1 | `.avif` | 识别为图片素材 |
| 上传 BMP | P1 | `.bmp` | 识别为图片素材 |
| 上传 JFIF | P1 | `.jfif` | 识别为图片素材 |
| 上传 ICO | P2 | `.ico` | 识别为图片素材 |
| 上传不支持文件 | P1 | `.txt` | 显示不支持类型，不入库 |

## 🎬 手动测试步骤

### 桌面端添加图片

1. 打开 Opentu 桌面端。
2. 进入任意画布。
3. 点击工具栏图片按钮，或使用快捷键添加图片。
4. 选择本地 PNG/JPG/WebP 图片。
5. 观察图片是否插入画布，且素材库中可正常预览。

### 空 MIME 图片兜底

1. 准备一张扩展名有效但系统 MIME 可能为空的图片，例如部分 `.jfif` 或从外部工具导出的 `.bmp`。
2. 分别通过工具栏添加、拖拽到画布、素材库上传三条路径导入。
3. 观察图片是否均被识别为图片，而不是不支持文件。

### 异常输入

1. 通过图片入口尝试选择或拖拽 `.txt` 文件。
2. 观察画布不应插入错误图片元素。
3. 素材库上传时应给出不支持类型提示。

## ⚠️ 风险与回归点

- SVG、ICO、AVIF 等格式的浏览器解码能力依赖运行环境，功能验收应以“识别和入库正确”为主，渲染异常需单独定位。
- 桌面端应继续使用本地路径型素材，避免大图片在前端形成额外内存峰值。
- 后续新增图片格式时，要同时更新 MIME 常量、扩展名映射、素材校验和测试用例。
